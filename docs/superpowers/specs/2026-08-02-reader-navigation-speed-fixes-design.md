# 阅读导航与播放倍速修复设计

## 目标

- 播放器倍速选择必须真实作用于正在使用的语音播放引擎，并在后续段落继续生效。
- 阅读到当前章末后继续向下滚动，应进入下一章；最后一章不重复触发。
- 章节目录支持按标题或章节序号快速搜索。
- 打开章节目录时，列表应自动定位到当前阅读章节。

## 方案选择

阅读续章采用“单章加载 + 章末过度滚动切章”。整本连续列表会显著增加长篇小说的内存、查询和进度同步复杂度；固定下一章按钮又不符合连续下滑的操作预期。当前方案保持现有数据边界，只在章末识别一次明确的继续滚动手势。

目录继续使用底部弹层，但改为可搜索、可按索引定位的列表。初次打开以当前章节索引作为列表起点；搜索结果按章节标题和一基序号过滤。

倍速沿现有播放链路传递：`PlayerPage` 发出速率变更，`NovelAudioHandler` 更新系统播放状态并调用 `PlaybackController`，`PlaybackCoordinator` 保存当前速率并传给可调速的语音 Provider。缓存音频通过 `just_audio` 调速；系统 TTS 通过 `FlutterTts.setSpeechRate` 调速。段落重新准备后再次应用用户选择，防止配置语速覆盖播放器倍速。

## 交互与边界

- 倍速选项保留 `0.8x / 1.0x / 1.25x / 1.5x`，重新进入播放器时读取当前 AudioHandler 速率。
- 章末过度滚动累计达到阈值后只触发一次，直到新章节加载完成才允许再次触发。
- 最后一章不执行切换。
- 目录搜索为空时显示空列表；清空搜索恢复全部章节并重新定位当前章。
- 选择当前章节只关闭目录，不重置进度。

## 错误处理

- 调速调用异步失败时，播放器仍保持可操作；AudioHandler 只在控制器成功后发布新速率。
- 切章继续复用现有数据库进度写入和章节加载错误页面。
- 搜索完全在内存中的章节元数据上执行，不新增数据库写入。

## 测试

- AudioHandler 将倍速传给控制器并发布新 PlaybackState。
- Coordinator 将倍速传给 Provider，并在下一段准备后重新应用。
- PlayerPage 点击倍速选项调用回调。
- ReaderPage 在章末继续滚动时选择下一章，最后一章不触发。
- 目录打开后当前章位于已构建区域并显示选中状态。
- 目录按标题和序号过滤。
