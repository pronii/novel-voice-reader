# 跨平台小说自动朗读 App 设计规格

日期：2026-07-31

## 1. 目标

创建一款面向个人使用的 Flutter 应用，同时支持 Android 和 iOS。用户可以导入本地 TXT 或 EPUB 小说，通过系统 TTS 离线朗读，或通过用户自行配置的 OpenAI TTS 兼容接口生成并播放高质量语音。

应用需要同时提供正文阅读模式和纯播放器模式，并支持后台播放、锁屏控制、阅读进度恢复，以及由用户指定数量的后续章节预下载。

## 2. 非目标

第一版不包含：

- 账号、会员、支付或运营后台
- 云端书架和多设备同步
- 在线书城或小说网站抓取
- PDF、OCR、漫画或有声书导入
- DRM 加密 EPUB
- 公开分享 API Key 或服务端代管密钥

## 3. 成功标准

用户能够在 Android 和 iPhone 上完成以下流程：

1. 从系统文件选择器导入 TXT 或 EPUB。
2. 查看自动识别的书名和章节。
3. 使用系统 TTS 开始离线朗读。
4. 配置一个 OpenAI TTS 兼容服务并切换为云端语音。
5. 在正文阅读模式中看到当前段落高亮和自动滚动。
6. 切换到纯播放器、后台或锁屏状态后继续播放。
7. 输入需要预下载的后续章节数量，并查看预计空间和下载进度。
8. 关闭并重新打开应用后恢复到最近确认的章节和段落。

## 4. 技术路线

采用单一 Flutter 工程共享 UI、领域逻辑、数据模型、解析流程、播放队列和缓存策略。

以下能力通过平台适配层实现：

- Android 和 iOS 文件访问
- 系统 TTS
- 后台音频与锁屏媒体控制
- 安全凭据存储
- 后台传输和系统调度

整体分层如下：

```text
Flutter UI
  |
Application Controllers
  |
Domain Services and Provider Interfaces
  |
Local Database / File Cache / Secure Storage / Platform Adapters
```

各层职责：

- UI：渲染状态并发送用户意图，不直接访问数据库或网络。
- Application Controllers：协调导入、阅读、朗读、下载和设置流程。
- Domain Services：处理章节、段落、播放队列、缓存键和进度规则。
- Provider Interfaces：隔离系统 TTS、云端 TTS、音频播放和后台任务实现。
- Infrastructure：负责数据库、文件、HTTP、安全存储和平台通道。

## 5. 功能与界面

### 5.1 书架

- 显示书名、封面、最近阅读时间和阅读进度。
- 提供 TXT/EPUB 导入。
- 支持打开、删除书籍和清理单本缓存。
- 删除书籍前显示将删除的正文索引和音频缓存大小。

### 5.2 阅读器

- 显示章节正文。
- 高亮当前朗读段落并自动滚动。
- 支持手动翻阅，用户主动选择段落后从该段开始朗读。
- 支持字号、行距、主题和深色模式。
- 提供进入纯播放器和章节目录的入口。

### 5.3 纯播放器

- 播放、暂停、上一段、下一段、上一章和下一章。
- 显示章节、段落进度及当前语音来源。
- 支持语速、定时关闭和播放模式切换。
- 后台和锁屏控制至少包含播放、暂停、上一段和下一段。

### 5.4 语音设置

- 在系统 TTS 和云端 TTS 之间切换。
- 系统 TTS 可选择已安装音色、语速和音调。
- 云端 TTS 可配置 Base URL、API Key、模型、音色、语速和输出格式。
- 提供连接测试；测试成功后才允许设为默认云端语音。
- API Key 只显示掩码，不提供明文回显。

### 5.5 缓存管理

- 用户输入要保留的后续章节数，可选择 0 到当前书籍剩余章节数中的任意整数，也可直接选择整本。
- 缓存窗口包含当前章节和指定数量的后续章节。
- 进入下一章后自动补齐缓存窗口。
- 显示预计大小、已用空间、排队数量和下载进度。
- 支持仅 Wi-Fi、允许移动网络、暂停、继续、取消和清理。
- 支持设置全局缓存上限。

## 6. 书籍导入与解析

### 6.1 TXT

- 优先检测 UTF-8、UTF-8 BOM 和 UTF-16。
- 无法可靠识别时尝试常见中文编码，并让用户确认或手动选择。
- 统一换行符，移除 BOM，但保留正文标点和自然段。
- 使用可配置的章节标题规则识别“第 X 章”“卷 X”等常见格式。
- 未识别到章节时，将全文作为单章导入，不阻止阅读。
- 解析结果保存为规范化章节和段落，不依赖原文件持续存在。

### 6.2 EPUB

- 读取 OPF 元数据、spine 阅读顺序和导航目录。
- 将 XHTML 内容转换为规范化段落，忽略脚本和展示样式。
- 优先使用 EPUB 目录标题；目录缺失时使用文档标题或顺序编号。
- 遇到加密、DRM、缺失 spine 或无法解析的内容时停止导入并给出明确错误。

### 6.3 段落标识

每个段落获得稳定的顺序号。播放位置使用 `bookId + chapterId + paragraphIndex` 表示，不依赖页面像素或临时 Widget 状态。

## 7. 朗读引擎

### 7.1 统一接口

系统 TTS 和云端 TTS 实现同一朗读 Provider 契约：

```text
prepare(segment, voiceConfig)
play()
pause()
resume()
stop()
seekToSegment(segmentId)
events -> state, position, completion, error
```

播放控制器只依赖该契约。切换 Provider 时先持久化当前位置、停止旧 Provider，再从当前段落启动新 Provider。

### 7.2 系统 TTS

- 直接朗读文本，不生成音频缓存。
- 按段落提交文本，以完成事件驱动高亮和进度推进。
- 系统音色不可用时回退到平台默认音色。
- Android 系统 TTS 暂停时记录当前段落；恢复时允许从当前段落开头重新朗读。iOS 在平台支持时从暂停位置继续。
- 蓝牙或耳机中断时遵循系统音频焦点规则暂停或恢复。

### 7.3 云端 TTS

- 兼容端点定义为 `POST {baseUrl}/v1/audio/speech`。
- 请求至少包含 `model`、`voice` 和 `input`。
- 可选配置仅在服务端支持时发送，例如 `response_format` 和 `speed`。
- 单个请求以自然段为优先边界；超出服务配置的字符上限时按句号、问号、感叹号等句末标点继续切分。
- 默认目标片段为 500 到 1000 个中文字符，但最终不得超过用户配置或服务返回的长度限制。
- 片段下载完成并通过非空、可解码校验后，使用原子重命名写入正式缓存路径。

“OpenAI 兼容”在第一版仅保证上述端点和字段契约，不承诺兼容厂商私有鉴权、异步任务或 WebSocket 协议。

## 8. 播放队列与进度

- 播放队列以段落语音片段为基本单位，以章节为预取边界。
- 当前片段播放完成后自动进入下一片段；章节结束后进入下一章。
- 每次开始新段落时写入候选进度。
- 段落完成、用户暂停、切换章节或应用进入后台时提交确认进度。
- 异常退出后从最后一次确认进度恢复，允许最多重复当前段落，不允许跳过未完成段落。
- 手动滚动不改变播放位置；只有用户点击“从这里朗读”才更新播放队列。

## 9. 缓存与预下载

### 9.1 缓存键

缓存键由以下内容的稳定摘要组成：

- 书籍和段落标识
- 规范化文本内容
- Base URL
- 模型
- 音色
- 语速
- 输出格式

API Key 不进入缓存键，也不写入缓存元数据。更改任何影响声音结果的配置都会创建新缓存版本。

### 9.2 预下载窗口

若用户设置后续章节数为 N，则目标窗口为当前章节到后续 N 章。设置为 0 时只允许按需生成当前播放片段；设置为整本时覆盖所有未完成章节。

补齐规则：

1. 优先保证当前播放片段和当前章节。
2. 按章节顺序下载后续内容。
3. 用户跳转章节后取消尚未开始且已离开目标窗口的低优先级任务。
4. 已完成缓存不立即删除，交由空间上限和用户清理操作处理。

### 9.3 空间估算

在服务端未返回准确大小前，按朗读速度和目标码率估算，并明确标记为预计值。缓存管理页显示实际占用。

达到缓存上限时：

1. 停止新的预下载。
2. 保留当前章节和用户明确下载的内容。
3. 提示用户清理或提高上限。
4. 不影响系统 TTS 继续朗读。

## 10. 跨平台后台行为

### 10.1 Android

- 使用前台媒体服务保持后台播放并提供通知控制。
- 使用持久后台任务执行受网络条件约束的预下载。
- 系统重启后恢复未完成队列，但不自动开始朗读。

### 10.2 iOS

- 启用音频后台模式，支持后台播放和锁屏媒体控制。
- 已提交给系统后台传输会话的文件传输可在应用挂起后继续。
- 自动补齐新的预下载任务受 iOS 调度控制，不能保证在应用被用户彻底结束后立即运行。
- 用户下次打开应用或系统授予后台刷新时间时重新计算并补齐缓存窗口。

产品界面不得宣称 Android 与 iOS 的后台预下载时效完全一致。

## 11. 数据模型

核心实体：

- `Book`：书籍元数据、来源类型、导入时间和最近阅读时间。
- `Chapter`：书籍归属、顺序、标题和规范化正文引用。
- `Paragraph`：章节归属、顺序和规范化文本。
- `ReadingProgress`：当前章节、段落、更新时间和确认状态。
- `VoiceProfile`：Provider 类型及非敏感语音配置。
- `DownloadPolicy`：后续章节数、网络条件和空间上限。
- `AudioCacheEntry`：缓存键、文件路径、大小、状态和访问时间。
- `DownloadJob`：目标片段、优先级、重试次数和任务状态。

API Key 存储在 Android Keystore 或 iOS Keychain 支持的安全存储中，数据库仅保存对应配置是否已设置。

## 12. 错误处理

- 云端请求使用有限次数的指数退避重试，并区分鉴权失败、限流、网络错误和服务端错误。
- 鉴权失败或配置错误时暂停云端队列，提示用户修复配置，不持续消耗请求。
- 当前片段云端播放失败时提供“一键改用系统语音继续”。
- 网络中断时保留队列，满足网络策略后继续。
- 音频文件校验失败时删除临时文件并重试，不播放部分文件。
- 导入失败不会留下半成品书籍；数据库写入和正文文件落盘使用事务式提交。
- 删除书籍或清理缓存时，先停止关联播放和下载任务，再删除记录和文件。

## 13. 隐私与安全

- 默认不采集账号、通讯录、位置或广告标识。
- 系统 TTS 文本不离开设备。
- 使用云端 TTS 时，仅向用户配置的端点发送当前生成所需的小说文本和语音参数。
- 第一次启用云端 TTS 前明确提示文本会发送到第三方服务。
- API Key 使用系统安全存储，不进入日志、崩溃报告、数据库或导出文件。
- 日志对 URL 查询参数、请求头和响应正文进行脱敏。
- 生产构建默认关闭详细网络日志。

## 14. 测试策略

### 14.1 单元测试

- TXT 编码、章节规则和段落规范化。
- EPUB spine、目录和 XHTML 转换。
- 播放队列推进、章节跳转和进度确认。
- 云端文本切分和请求序列化。
- 缓存键稳定性、窗口计算和空间淘汰。
- 错误分类、重试和 Provider 回退。

### 14.2 集成测试

- 导入文件到数据库提交的完整流程。
- 模拟 TTS 服务的成功、限流、鉴权失败、损坏音频和断网恢复。
- 音频缓存写入、校验、复用和配置变更失效。
- 安全存储读写及日志脱敏。

### 14.3 端到端与真机测试

- Android 和 iOS 各至少一台真机。
- 前台、后台、锁屏、耳机控制、来电或音频焦点中断。
- 预下载在 Wi-Fi/移动网络切换、空间不足和应用重启后的恢复。
- 10 万字以上 TXT 和多章节 EPUB 的导入与连续播放。
- 深色模式、大字体和窄屏设备下无文本或控件重叠。

## 15. MVP 验收条件

- 两个平台均可成功构建并安装。
- TXT 和非 DRM EPUB 能导入、解析并出现在书架。
- 系统 TTS 可以连续朗读并正确推进高亮和进度。
- 符合本规格契约的模拟云端 TTS 服务可以生成、缓存并连续播放音频。
- 后台和锁屏控制在两端真机上通过测试。
- 用户设置的后续章节数会正确生成目标缓存窗口。
- 断网、鉴权失败、损坏音频和空间不足均有可恢复行为。
- 重启应用后恢复到最后确认的章节和段落。
- API Key 不出现在数据库、普通日志或缓存元数据中。
